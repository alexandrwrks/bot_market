# SportMarket Bot

Telegram-бот для продажи спортивного питания и сопутствующих товаров.

Сейчас проект находится в активной разработке.

README написан так, чтобы новый человек в команде мог быстро:
- понять, что это за проект;
- развернуть его локально;
- запустить бота;
- сориентироваться по структуре репозитория;
- понять, куда лучше добавлять новый код.

## Что уже есть

- запуск бота через `aiogram`;
- точка входа через `python -m app.main`;
- стартовое меню;
- inline-кнопки;
- разделы:
  - каталог;
  - корзина;
  - заказы;
- тестовая навигация по товарам;
- изображения товаров из папки `images/`;
- заготовки для работы с пользователями и БД.

## Что планируется дальше

- полноценная работа с товарами через БД;
- карточки товаров с описанием, ценой и фото;
- корзина с реальными товарами пользователя;
- оформление заказа;
- административная часть для добавления и редактирования товаров;
- улучшение структуры обработчиков и сервисов.

## Быстрый старт

### 1. Клонировать репозиторий

```bash
git clone <URL_РЕПОЗИТОРИЯ>
cd bot_market
```

### 2. Создать виртуальное окружение

Windows PowerShell:

```powershell
python -m venv venv
.\venv\Scripts\Activate.ps1
```

### 3. Установить зависимости

```bash
pip install -r requirements.txt
```

Если `requirements.txt` ещё не обновлён или есть расхождения, можно использовать базовый список:

```bash
pip install aiogram python-dotenv aiosqlite
```

### 4. Создать файл `.env`

В корне проекта создай файл `.env`:

```env
BOT_TOKEN=your_telegram_bot_token
DATA_BASE_NAME=users.db
```

Минимально для запуска бота нужен `BOT_TOKEN`.

`DATA_BASE_NAME` нужен для частей проекта, связанных с локальной базой данных. 

### 5. Запустить бота

Из корня проекта:

```bash
python -m app.main
```

Если всё в порядке, в консоли появится сообщение:

```text
Бот успешно запущен
```

## За что отвечает каждая часть

### `app/main.py`

Главная точка входа в проект.

Здесь:
- загружается `.env`;
- создаются `Bot` и `Dispatcher`;
- подключаются роутеры;
- запускается polling.

### `app/services/config_hand.py`

Содержит список роутеров, которые подключаются при запуске бота.

Если добавляешь новый роутер, его нужно импортировать и зарегистрировать здесь.

### `app/handlers/`

Основные обработчики пользовательских действий:

- `start_hand.py` — команда `/start`;
- `categoties_hand.py` — переходы по каталогу;
- `basket_hand.py` — логика корзины;
- `orders_hand.py` — раздел заказов.

### `app/handler_service/`

Дополнительные обработчики для конкретных групп товаров или сценариев.

Например:
- `protein.py` — логика выбора вкуса протеина и связанных действий.

### `app/keyboards/`

Функции для сборки inline-клавиатур.

Туда лучше выносить только создание кнопок, без бизнес-логики.

### `images/`

Папка с локальными изображениями товаров.

Сейчас фото товаров берутся отсюда для тестирования, без привязки к БД.

## Как добавлять новый функционал

Рекомендуемый порядок работы:

1. Добавить или обновить клавиатуру в `app/keyboards/`
2. Добавить обработчик в `app/handlers/` или `app/handler_service/`
3. Подключить роутер в `app/services/config_hand.py`, если это новый роутер
4. Проверить запуск через `python -m app.main`
5. Протестировать сценарий в Telegram

## Рекомендации по стилю проекта

Чтобы код было удобно поддерживать всей команде:

- не смешивать клавиатуры и хендлеры в одном файле;
- не писать всю логику в `main.py`;
- для inline-кнопок использовать `callback_query`, а не `message`;
- функции клавиатур делать обычными `def`, если внутри нет `await`;
- давать понятные имена `callback_data`;
- большие сценарии выносить в отдельные файлы.

## Частые ошибки при запуске

### Ошибка `No module named 'app'`

Причина: проект запускается как файл, а не как модуль.

Неправильно:

```bash
python app/main.py
```

Правильно:

```bash
python -m app.main
```

### Ошибка `No module named 'aiogram'`

Причина: не активировано виртуальное окружение или зависимости не установлены.

Решение:

```powershell
.\venv\Scripts\Activate.ps1
pip install -r requirements.txt
```

### Ошибки с `reply_markup`

Обычно возникают, когда в `reply_markup` передают:
- функцию вместо результата её вызова;
- coroutine вместо готовой клавиатуры;
- не тот тип объекта

Правильный подход: в `reply_markup` должен попадать уже готовый `InlineKeyboardMarkup`.
